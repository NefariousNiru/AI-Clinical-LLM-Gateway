# Contributing

- Run `make` before pushing (format + lint + test).
- Keep PRs small and focused; include a brief design note for non-trivial changes.
- Update relevant docs in `docs/` and add/adjust tests.
- Discuss any changes to error codes or gRPC surface in an issue first.
- Write modular unit testable code and write unit tests for them 

## Commit hygiene

- Use conventional messages where possible (`feat:`, `fix:`, `docs:`).
- Reference the Issue ID in the body.
